# Issue #5: job report, log file, cgroup limits, version — prepare v0.3

## Context

Today the only outcome of `sbx run` is its exit code plus `sbx:` lines on stderr. Those lines are interleaved with the payload's own stderr, and the payload can forge them. Issue #5 asks for a trustworthy, machine-readable outcome:
- a root-owned JSON report
- sbx's logs moved off the payload's stderr
- cgroup v2 limits with OOM detection
- `sbx version` printing the tag

This becomes v0.3.

**User decisions:**
- **Logs:** `--log FILE` / `SBX_LOG_FILE`, streamed as they happen. Without it, logs stay on stderr as in v0.2.
- **cgroup:** a required `[cgroup]` table with `mode = "off" | "delegated"`. This is a breaking change: v0.2 policy files no longer parse. The shipped policies say `"off"`.


## User-visible behaviour

**New flags and variables:**
- `--report FILE` / `SBX_REPORT_FILE` and `--log FILE` / `SBX_LOG_FILE`.
- Both go in `policy::ENV_VARS`, `Overrides` (+`merge`), `parse_flags`, USAGE and the README table.
- All three commands accept them:
  - `run` uses them.
  - `probe` checks both destinations: a trial temp file is created and then unlinked.
  - `policy` sends its warnings to the log file.

**Policy:**
```toml
[cgroup]
mode = "off"            # or "delegated" with:
# memory_mb = 512 | "unlimited"   (memory.max; swap off)
# pids = 256 | "unlimited"        (pids.max; counts threads)
```
- The raw serde struct (`deny_unknown_fields`) goes through `try_from` into `enum CgroupCfg { Off, Delegated { memory_mb: Limit, pids: Limit } }`.
- `memory_mb` or `pids` together with `mode = "off"` is an error.
- A missing `[cgroup]` table is an error with the hint "new in v0.3: add `[cgroup]` with `mode = \"off\"`".
- The overflow check is shared with `validate_limits`.
- `delegated` with a non-root sbx is refused.
- `sbx policy` prints the table back.

**Report** (JSON via `serde_json`, mode 0600, written once, after the run is fully torn down):
```json
{ "sbx_version": "v0.3", "exit_code": 137,
  "program": {"exited": 0} | {"signaled": 9} | null,
  "timed_out": false,
  "setup_error": {"stage": "policy", "messages": ["..."]} | null,
  "supervisor_error": "..." | null,
  "denials": [{"syscall": "socket", "count": 2}],
  "killed_after_exit": 1 | null,
  "wall_ms": 1234 | null,
  "rusage": {"user_ms": 1, "sys_ms": 1, "max_rss_kib": 1} | null,
  "cgroup": {"memory_mb": 512|"unlimited", "pids": 256|"unlimited", "memory_peak_kib": 1,
             "oom_kills": 0, "pids_max_hits": 0, "user_ms": 1, "sys_ms": 1} | null }
```
- `killed_after_exit` is `null` when sbx had already killed the tree (timeout, second signal, fatal error).
- `max_rss_kib` is the largest single process. The cgroup's `memory_peak_kib` is the peak of the whole tree.

**`sbx version`:**
- prints `sbx <SBX_VERSION>`, which is `git describe --tags --always --dirty --match 'v*'` at build time
- prints `sbx unknown (Cargo.toml 0.3.0)` when the variable was not set, so rust-analyzer and plain `cargo check` keep working
- the report carries the same string

## Design by component

**`src/report.rs` (new): stages, outcome, destinations**
- **Stages.** `enum Stage` (snake_case serde) covers:
  - pre-fork: `policy report log env program capabilities slot stdio dns cgroup landlock seccomp launch`
  - in the child, today's strings: `setsid chdir setrlimit identity pdeathsig no_new_privs landlock seccomp close_range signals execve`
  - after fork: `listener services`
- `Stage::as_str` / `from_prefix` replace the string literals in `supervisor::child`. The `"stage: msg"` pipe format stays.
- **Errors.** `struct SetupError { stage, errors: Vec<String> }` plus a `trait At` (`.at(Stage::X)`) for `Result<_, String>` and `Result<_, Vec<String>>`.
- **Outcome.** `Outcome` is an enum `SetupFailed{..} | Ran{..}`, serialized to the flat schema above.
- **Pure helpers.** A `fn secure_dir(chain: &[DirMeta], euid) -> Result<(), String>` predicate is separate from the IO that collects the metadata. Its rule:
  - every ancestor directory is owned by root or the euid
  - no ancestor is group- or other-writable
  - a sticky ancestor is allowed only if the next component is owned by root or the euid
- **`Destination::open(path)`.** Requires an absolute path, a plain file name and a canonical parent. Collects the ancestor chain and checks it with `secure_dir`. Opens the dirfd with `O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC` (not `O_PATH`: `fsync` needs a real fd).
- **Non-root sbx.** After the policy resolves, `check_policy(&Policy)` additionally requires that `Policy::covered(dir,'w')` and `covered(dir,'r')` are both false (`src/policy.rs:800`).
- **Report open.** Open the destination, then `unlinkat` any stale report, so a missing report always means sbx failed early or was killed.
- **`write_report`.** Creates `.NAME.PID.tmp` with `O_CREAT|O_EXCL|O_NOFOLLOW` and `fchmod 0600`, writes, `fsync`s, `renameat`s over the target and `fsync`s the dir. If the write fails, sbx logs the error and exits 125.

**`src/log.rs`: sink and escaping**
- `static SINK: OnceLock<File>`.
- `open_file(Destination)` opens the file with `openat(O_WRONLY|O_APPEND|O_CREAT|O_NOFOLLOW|O_NONBLOCK|O_NOCTTY|O_CLOEXEC, 0600)`, then `fstat` must show:
  - a regular file
  - owned by the euid
  - `mode & 0o077 == 0`
  - `nlink == 1`
- Every line is formatted into one `String`, then sent with a single `write` to the sink, or to stderr when there is no sink. The threads log concurrently.
- **Write failure:** the line and the error go to stderr, the error is recorded for the report, and the fatal signal is raised directly, not through the logger.
- `pub fn untrusted(&str) -> String` escapes control characters, so a payload can't forge log lines with newlines. Apply it in `notify::comm_of`/`describe` and to DNS labels (`dns.rs:71`, `read_name`).
- `fatal_signal()` moves here from `notify.rs`.
- `raise_fatal` also stores the first message in a `OnceLock`, which becomes `supervisor_error`.

**`src/main.rs`**
- `real_main` for `run`:
  1. flags and env
  2. `Destination::open` for report and log (on error: stderr, exit 125, no report)
  3. `log::open_file`
  4. `run(ov, ...) -> Result<Outcome, SetupError>`
  5. log the outcome
  6. `write_report`
  7. exit code
- `run()` takes `Overrides`, so policy errors carry `Stage::Policy`. `.map_err(one)?` becomes `.at(Stage::X)?`. All guards (slot, resolv.conf, cgroup) are dropped inside `run`, before the report is written.
- **Signals are blocked first thing in `run`.** `supervisor::block_signals` moves here from `launch`, so a SIGTERM during setup cannot leave resolv.conf or the cgroup half-changed. Right before fork, `sigpending` is checked: a pending termination signal aborts with `Stage::Launch`.
- `sbx version` uses the new `VERSION` constant.

**`src/supervisor.rs`**
- `run`/`launch` return `Result<Outcome, SetupError>`.
- **Waits.** One `wait4` wrapper feeds a pure `Usage` accumulator (sum of user/sys, max of maxrss). It is used by `wait_for`, `reap`, `reap_all` and the `sigtimedwait` error path. `RUSAGE_CHILDREN` is not used, because capability checks fork children of their own.
- **`killed_after_exit`.** A snapshot right after the main child is reaped and before `kill_tree`. The delegated cgroup reads `cgroup.procs`. Otherwise a `/proc` walk counts the processes that are not zombies:
  - PID 1: every pid except 1
  - subreaper: descendants found by following ppid
  - it reuses the stat parsing in `own_children`
- **`kill_tree`** writes `cgroup.kill` first when delegated.
- **Shutdown.** The dispatcher's `JoinHandle` is kept. After `reap_all`, a bounded join gives denial counts that won't change any more (`notify::Dispatcher::spawn` returns it).
- **`child()`.** When delegated, its first step writes `"0"` to the pre-opened `sbx-sandbox/cgroup.procs` fd (`Stage::Cgroup`). If the listener receives EOF while `oom_kill` is above 0, the error gets the hint "cgroup.memory_mb too small".

**`src/notify.rs`**
- `Stats` gets `denials: Mutex<BTreeMap<String, u64>>`, incremented in `deny()` with `syscall_name(n.data.nr)`. Egress denials count as `connect`.
- The `Stats::summary` "repeated" lines stay.

**`src/cgroup.rs` (new): delegated mode**
- **`setup(&Policy) -> Result<Delegation, String>`** runs before fork with signals blocked. Every step registers its undo, so a failure unwinds:
  1. cgroup2 at `/sys/fs/cgroup` (statfs magic), and `/proc/self/cgroup` is exactly `0::P` with no `/..`.
  2. `C/cgroup.procs` is exactly `[getpid()]`. Otherwise the error names the other processes.
  3. `cgroup.type` is `domain`, `cgroup.controllers` includes `memory` and `pids`, and there is no leftover `sbx-supervisor` or `sbx-sandbox`. If there is, say how to remove it.
  4. `memory_mb` is below `C/memory.max` when that is a number.
  5. `mkdir C/sbx-supervisor` and move sbx into it, then write `+memory +pids` to `C/cgroup.subtree_control`.
  6. `mkdir C/sbx-sandbox`, then write `memory.max`, `memory.swap.max=0`, `memory.oom.group=1` and `pids.max`, reading each one back.
     - `memory.swap.max` may only be missing when `/proc/swaps` lists no active swap.
     - `cgroup.kill`, `memory.peak`, `memory.events`, `pids.events` and `cpu.stat` must exist.
  7. Open `sbx-sandbox/cgroup.procs` and the sandbox dirfd.
- Errors name the cause: EROFS with what each runtime needs, missing controllers, hybrid v1, other processes.
- **`Delegation::finish() -> (CgroupStats, Vec<String>)`:**
  1. `cgroup.kill`
  2. wait until `cgroup.events` shows `populated 0` (bounded)
  3. read `memory.events` `oom_kill`, `memory.peak`, `pids.events` `max` and `cpu.stat`
  4. `rmdir sbx-sandbox`
  5. write `-memory -pids` to C
  6. move sbx back to C
  7. `rmdir sbx-supervisor`

  `Drop` is only a backstop that logs.
- **Probe:** `capabilities::check` gets a `cgroup` check when the mode is `delegated`, which runs `setup()` and then `finish()` as a reversible trial (the same messages as `run`).
- Value formatting is pure (`Limit` to `"max"`/bytes) and so is stats parsing (`key value` lines). Both get property tests.

**Version and build**
- `Cargo.toml` goes to `0.3.0`; add `serde_json`, and `proptest` as a dev-dependency. `Cargo.lock` is updated offline from the cache.
- **Makefile:** `SBX_VERSION ?= $(shell git describe --tags --always --dirty --match 'v*')`, with an `$(error)` if empty. It is exported to cargo and passed as `--build-arg SBX_VERSION` plus the label `org.opencontainers.image.version`.
- **Dockerfile:** the build stage gets `ARG SBX_VERSION` with no default and checks `test -n`. The build can't run git describe because `.dockerignore` excludes `.git`.
- **ci.yml:** set `fetch-depth: 0` for both checkouts. On `v*` tags, add a step that fails unless `make print-SBX_VERSION` equals `$GITHUB_REF_NAME`.

**Shipped policies and docs**

  - "Log file"

## Tests

**Unit and property tests, pure logic only:**
- the `Usage` accumulator (sum and max laws)
- the wait status → `program` mapping
- the `Stage` pipe-prefix round trip, over every variant
- the `secure_dir` predicate, over owner/mode/sticky combinations
- `CgroupCfg` parse/validate: an off table with limits, a missing table, overflow
- cgroup value formatting, and stats-line parsing
- `log::untrusted`: the output never contains control characters

**`tests/smoke.py`:**
- `sbx()` gains an optional report: each run passes `--report`, and the harness asserts `report.exit_code == rc`. Non-root wrapped runs are excluded.
- New "report/log" section:
  - an exit, a signal, a timeout (`timed_out`, 124) and a denial (`socket` in mode none)
  - `killed_after_exit` for `setsid sleep &`
  - these stages: `policy`, `capabilities` (non-root), `execve` (127), `report` (sandbox-writable or symlinked dir)
  - a stale report is removed at start
  - a symlink at the target is replaced, not followed
  - the report is root-owned and 0600
  - with `--log`, stderr has no `sbx:` lines, the log has them, and the payload can't read it
- **cgroup section,** gated by `TEST_REQUIRE_CGROUP` (true/false, like Landlock):
  - Not delegated: `delegated` is refused and probe shows MISSING with the reason.
  - Delegated:
    - the harness moves its own pids to `C0/harness`, enables controllers, and runs each sbx in a fresh `C0/run-N` through a `sh` wrapper
    - checks: probe leaves no trace; OOM gives 137 with `oom_kills ≥ 1`; the pids limit is hit; leftovers are killed and the cgroup removed; other processes in C are refused; `memory_mb` at or above the parent's limit is refused; the payload cannot write `memory.max`
- **`make smoke`:** test container flags for a writable cgroup (expected: podman `--systemd=always`, to be verified in the podman machine). The Makefile takes a `SMOKE_CGROUP` variable for the flags and the gate.

**`tests/image-checks.sh`:**
- `sbx version` equals `sbx $SBX_VERSION`
- a PID-1 report into a named volume, read back with a second container
- `delegated` refused on the default read-only cgroupfs

**Elsewhere:**
- `tests/live.py` prints cgroup facts and runs `sbx probe` with a delegated policy, with `TEST_REQUIRE_CGROUP=false` on Cloud Run.
- `tests/run-local.sh` wraps the suite in `systemd-run --scope -p Delegate=yes` when the gate is true.
