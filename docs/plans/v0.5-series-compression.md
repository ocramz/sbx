# v0.5, part 3 of 3: compressed series, in memory and on disk

Follows [v0.5-series.md](v0.5-series.md) and [v0.5-series-processes.md](v0.5-series-processes.md). v0.5 is released after this part.

## Context

A series of up to `max_samples` rows, each with up to `max_processes` entries, costs tens of bytes per number in plain form. Memory figures change slowly from one sample to the next, so their deltas are small.

**User decision:** both kinds of compression.
- **In memory:** delta, zigzag and LEB128 varints. This lowers typical use. The worst-case bound stays as it is.
- **On disk:** optionally gzip the written file.

## User-visible behaviour

- **Policy:** `[measure.series] compression = "none" | "gzip"` is required with `mode = "on"`. It applies to the written file only.
- **File:** with `"gzip"`, the file is the gzip of the same JSON. The magic bytes identify it, and sbx does not look at the file name.
- **Log:** sbx logs the series' in-memory size and the number of rows when it finishes.

## Design

- **Codec (`src/series/codec.rs`, pure):**
  - `zigzag` and `leb128` encoding and decoding
  - a column is a `Vec<u8>` of varints, each the zigzag of the wrapping delta from the previous value
  - an optional column encodes `null` as 0 and a value v as zigzag(delta) + 1; a `null` does not change the previous value
  - per-process values (slot, anon, file, shmem) are deltas from the entry at the same rank in the previous row that reached that rank; a rank never reached before is a delta from 0
- **Store:**
  - `MemorySeries` keeps its API, but stores each column as an append-only encoded buffer plus the last decoded values
  - recording only ever stops, so nothing is re-encoded
  - the serializer decodes the columns while streaming
  - a row lists `min(max_processes, live_processes)` processes, so neither a per-entry `row` column nor a count per row is stored: `process_rows.row` is rebuilt from `live_processes`
  - the cgroup shmem column holds a value only for the rows whose `memory.stat` read succeeded, so a row cannot have one cgroup figure without the other
- **Bound:** `bound()` becomes the encoded worst case: 10 bytes per u64 varint and 5 per u32 one (the zigzag of a delta between two u32 is below 2^33), plus the process table, the state per rank and the writer's decoding scratch.

**User decision (while implementing):** per-rank deltas instead of per-slot ones. Per-slot deltas need the last figures of every slot in the encoder, and again in the decoder while it writes: about 32 bytes more per listed process in the worst case, which puts 50000 samples × 32 processes with one tmpfs mount at about 278 MiB, above the 256 MiB ceiling. Per-rank deltas keep only one row of state, and that series' worst case stays about 229 MiB.
- **Gzip:**
  - `flate2 = "1"` with its default pure-Rust backend (miniz_oxide)
  - `GzEncoder` wraps the writer inside `Destination::write_atomic_with`, and `finish()`'s error counts as a write error
