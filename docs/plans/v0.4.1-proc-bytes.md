# v0.4.1: read /proc as bytes; no stale report

## Context

Several readers of `/proc` use `read_to_string`, which fails on bytes that are not UTF-8. A process name (comm) can hold any byte but NUL. The sandbox sets it with `prctl(PR_SET_NAME)`, which seccomp allows. The kernel writes it unescaped in `/proc/<pid>/stat`, and in `/proc/<pid>/status` it escapes only `\n` and `\\`. So a process named `"\xff"` makes these reads fail:

- **`supervisor::proc_table`** drops the process silently: `read_to_string(...).ok()?`. Its callers:
  - `own_children`, from `kill_tree` and `reap_all`. When sbx is not PID 1 and has no delegated cgroup, a sandboxed process that left the process group with `setsid` and renamed itself is never sent SIGKILL. It outlives sbx (`reap_all` gives up after 5 s). This is the setup the README describes for a server that spawns sbx on Cloud Run.
  - `live_descendants`: the process and its whole subtree are never sampled.
  - `leftovers` without a cgroup: `killed_after_exit` is too low.
- **`memory::proc_mem`** logs the failure once and skips the process, and its memfds too.
- **`capabilities::uid_unused`** skips the process, so a survivor at the sandbox uid passes the check that guards runs without Landlock.
- **`notify::tgid_of`** fails, which is fatal with `on_violation = "kill"`: exit 125 blames sbx. **`notify::comm_of`** prints `<exited>`.

Separately, `remove_stale` for the report runs only in `run_and_report`, after `Outputs::open` has also opened the log. A bad `--log` path therefore leaves the previous run's report in place, which contradicts the README ("a missing report means sbx failed early").

## Changes

- **`src/supervisor.rs`:**
  - pure `ProcStat::parse(&[u8]) -> Option<ProcStat { state_zombie: bool, ppid }>`. The name lies between the first `(` and the last `)`, and the fields after it are ASCII.
  - `proc_table` reads bytes and uses it. A read error other than ENOENT/ESRCH is logged once per run instead of being dropped.
- **Status readers:** `memory::proc_mem`, `capabilities::uid_unused` and `notify::tgid_of` read `status` as bytes and parse `String::from_utf8_lossy` of it. The fields they read are ASCII, and only `Name:` can hold other bytes.
- **`src/log.rs`:** `untrusted_bytes(&[u8]) -> String`. Valid UTF-8 goes through `untrusted`, and each invalid byte becomes `\xNN` (`Utf8Chunks`).
  - `notify::comm_of` reads bytes through it.
  - `uid_unused` names processes through it.
- **`src/main.rs` `Outputs::open`:** for `sbx run`, the report is opened and its stale file removed before the log is opened. `probe` and `policy` remove nothing. `run_and_report` no longer removes.

## Tests

- **Property tests:**
  - `stat_parsing_finds_the_fields_whatever_the_name`: render a stat line with an arbitrary name (any bytes but NUL, including `)`, `(`, spaces, `\n` and invalid UTF-8), then parse it back to the same state and ppid.
  - `status_parsing_survives_any_process_name`: `ProcMem::parse_status` and `tgid` parsing of a status rendered with the kernel's escaping of an arbitrary name.
  - `untrusted_bytes_escapes_exactly_controls_and_invalid_bytes`: no control characters in the output, the output equals `untrusted` for valid UTF-8, and each invalid byte appears as `\xNN`.
- **`tests/smoke.py`, "process supervision":**
  - a program renames itself to `"\xff"` (ctypes `prctl(PR_SET_NAME)`) and `setsid`s a `sleep 300`, which inherits the name. sbx is not PID 1 in the suite, and this section has no cgroup. The sleep must be gone after sbx exits, and the report must say `killed_after_exit == 1`.
  - with sampling on, a renamed process holding a 32 MiB heap must show in `memory.max_anon_kib`.
  - Run the new tests against the v0.4 image first: they must fail there.
- **`tests/smoke.py`, report:** a bad `--log` path leaves no report behind.
