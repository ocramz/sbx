# v0.5, part 1 of 3: the memory time series (exact samples, aggregates)

Parts: this one; [v0.5-series-processes.md](v0.5-series-processes.md) (per-process entries); [v0.5-series-compression.md](v0.5-series-compression.md) (in-memory encoding, gzip). v0.5 is released after part 3. Builds on [v0.4.1-proc-bytes.md](v0.4.1-proc-bytes.md).

## Context

Memory sampling (`[measure] memory_sample_ms`) folds each sample into running peaks and discards it, so only the peaks reach the report. Users want the option to get every sample. Part 1 writes the per-sample aggregates to a separate file, with timestamps, in bounded memory.

**User decisions:**
- A separate file, `--series FILE` / `SBX_SERIES_FILE`; the report keeps its 12 keys.
- Exact samples only, no bucketing or downsampling.
- At most `max_samples` are kept. After that sbx stops recording and counts what it leaves out. The sample taken after the program exits is always kept.

**Defaults chosen:**
- **Policy and flag.** The policy says how a series is made, the flag says where it goes.
  - `--series` with `[measure.series] mode = "off"` is refused.
  - `mode = "on"` without `--series` collects nothing.
- **When the file is written.** Only when the program ran. It is removed when sbx starts, so after a setup failure there is no file, and the report has the error.
- **Failed writes.** A failed series write sets exit 125 and `supervisor_error` before the report is written, so the report's `exit_code` stays sbx's exit code.
- **Time origin.** Time is `t_us`, measured from the same origin as `wall_ms`.

## User-visible behaviour

**Policy.** A new required sub-table, refused when sampling is off unless its mode is off:
```toml
[measure.series]
mode = "off"           # the shipped policies; "off" takes no other field
# or
mode = "on"            # needs memory_sample_ms > 0
max_samples = 50000    # 1..=1_000_000
```
- A missing table is an error with the hint: "[measure.series] is new in sbx v0.5; add it with mode = "off" to keep v0.4's behaviour".
- The v0.4 hint for a missing `[measure]` now names `[measure.series]` too.
- The worst-case memory, `series::bound(max_samples, n_tmpfs, cgroup delegated)`, must stay under 256 MiB, and the error names the bound.
- Breaking change: v0.5.0.

**Flags.**
- `--series FILE` / `SBX_SERIES_FILE`, for `run` and `probe`, with the same path rules as `--report`.
- Refused when the path is the same as `--report` or `--log`.
- A new stage, `series`, after `log`, for the policy-dependent checks: the mode is on, and the sandbox cannot reach the directory.
- `sbx probe --series FILE` checks that sbx can write there.

**File.** Compact JSON with mode 0600, replaced atomically like the report:
```json
{"sbx_version": "v0.5",
 "memory": {"interval_ms": 20, "max_samples": 50000, "samples": 153, "dropped": 0,
   "rows": {"t_us": [], "live_processes": [],
            "max_anon_kib": [], "max_file_kib": [], "max_shmem_kib": [], "tree_anon_kib": [],
            "memfd_kib": [], "sysv_shm_kib": [], "tmpfs_kib": {"/dev/shm": []},
            "cgroup_anon_kib": [], "cgroup_shmem_kib": []}}}
```
- **Rows and order.** Each row is one sample as read, in order.
- **Sample counts.** `samples` is how many samples were taken, and `dropped` how many were not kept: they came after the `max_samples`th, but before the final one.
- **Columns.** `max_*_kib` is the largest single process in the sample. The maximum of each column over the rows equals the report's figure whenever `dropped = 0`.
- **Last row.** The last row is the sample taken right after the program's process was reaped.
- **`null`.** `null` marks a failed read in that sample: SysV, one tmpfs mount, or `memory.stat`. The cgroup columns are `null` as a whole without a delegated cgroup.
- **Future metrics.** Future time-series metrics get their own key next to `memory`.

## Design by component

- **`src/policy.rs`:**
  - `SeriesCfg { Off, On { max_samples: NonZeroU32 } }` through `RawSeries { mode, max_samples: Option }` (`deny_unknown_fields`, `skip_serializing_if` as `RawCgroup` does). Fields given with `"off"`, or missing with `"on"`, are refused.
  - `MeasureCfg::Sampled { interval_ms, tmpfs, series }`. `RawMeasure` gains `series` as its last field. `Off` with series on is a `TryFrom` error.
  - `validate_measure` checks the bounds and `series::bound`.
- **`src/main.rs` and Overrides:**
  - `series: Option<PathBuf>` from `--series` and `SBX_SERIES_FILE`, in USAGE.
  - `Outputs` gains `series`, opened after the report and, for `run`, `remove_stale`d at once. It is refused when it equals the report's or the log's path (same directory and name).
- **`src/report.rs`:**
  - `Stage::Series` after `Log`, giving 25 stages, with the README list updated.
  - `Ran` gains `series: Option<MemorySeries>`.
  - `series_json`, written by the caller.
- **`src/series.rs` (new, pure):**
  - `Row` is a fixed set of numbers, plus one `Option<u64>` per tmpfs mount by index, and optional SysV and cgroup figures. `Row::of(t_us, &Sample)`.
  - `MemorySeries { spec, rows, samples, dropped }`.
  - `push(t_us, &Sample, When::{Running, Final})`: a running sample is kept while `rows < max_samples`; the final one always is.
  - `bound()`: a fixed byte cost per row.
  - A streaming `Serialize` into columns (`collect_seq` over the rows).
- **`src/memory.rs`:**
  - `Sample`'s SysV figure and each tmpfs figure become `Option`. `None` is a failed read, and `Peaks::of` skips it, so the report does not change.
  - `Sample` gains `live_processes`, the number of processes read.
  - `Sampler::new(cfg, uid, series: Option<SeriesSpec>)`.
  - `sample(at: Duration, When, live, present, cg)`.
  - `finish() -> (MemoryReport, Option<MemorySeries>)`. It logs the series size.
- **`src/supervisor.rs`:**
  - The running samples get `started.elapsed()`, and the post-reap sample `When::Final`.
  - `Ran.series`.
- **`src/destination.rs`:** `write_atomic_with(FnOnce(&mut dyn Write) -> io::Result<()>)`, with `write_atomic` delegating to it.
- **`run_and_report`:**
  - For `Outcome::Ran` with a series, write it first.
  - On failure, log the error, set `exit_code = 125` and `supervisor_error` (unless one is already set), then write the report.

## Tests

- **Property tests:**
  - `kept_rows_are_the_first_samples_and_the_final_one`; `samples = rows + dropped`.
  - `the_series_agrees_with_the_report`: with nothing dropped, the maximum of each column equals the `MemoryReport` figure. It is never above it.
  - `every_column_has_one_entry_per_row_and_null_exactly_where_reads_failed`, on the JSON.
  - `series_settings_survive_sbx_policy`.
  - `the_bound_covers_every_series_the_spec_allows`: `bound()` ≥ the cost of any full series.
- **Unit tests:**
  - each refusal: fields with "off", a missing `max_samples`, series on with sampling off, the limits, the ceiling
  - the two hints
  - the stage round-trip with 25 stages
- **`tests/smoke.py`, a new section "time series":**
  - the file exists with mode 0600; the column maxima equal the report's `memory` figures; the last `t_us` is close to `wall_ms`
  - a small `max_samples` gives `dropped > 0`, and the last row is still the post-exit one
  - refused: `--series` with the mode off, the mode on with sampling off, the same path as `--report`, a ceiling overflow
  - a stale file is removed; no file after a setup failure
  - `sbx probe --series` checks the destination
  - the report check still counts 12 keys
