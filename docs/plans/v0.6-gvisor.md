# v0.6: a policy filter without the listener, for gVisor (#18)

## Context

Modal runs GPUs under gVisor alone, and sbx v0.5 cannot start there. Measured on Modal's gVisor (`4.19.0-gvisor`) on 2026-11-26:
- `SECCOMP_FILTER_FLAG_NEW_LISTENER` is refused with `EINVAL`: there is no seccomp user notification.
- Plain filters work: `SECCOMP_RET_ERRNO`, `SECCOMP_RET_KILL_PROCESS` (SIGSYS), stacking, inheritance across `fork` and `execve`, and programs of thousands of instructions.
- Everything else sbx needs works with `landlock.abi = "off"` and `cgroup.mode = "off"`.

So the listener is the one thing that stops sbx.

**User decision:** the gVisor integration test runs in a Modal sandbox, driven by a uv script, with the credentials Modal's client reads from `~/.modal.toml`.

## User-visible behaviour

- **Policy:** `[seccomp] notify = "listener" | "off"` is required. This is breaking (v0.6): "to keep v0.5's behaviour, add `notify = "listener"`". A policy without it is refused with that hint.
- **`notify = "off"`:**
  - A policy match returns the policy's verdict from the kernel: `EPERM` with `on_violation = "errno"`, `SECCOMP_RET_KILL_PROCESS` (SIGSYS, exit 159) with `"kill"`. The prelude is unchanged.
  - Matches are neither logged nor counted. The report's `denials` is `null`, meaning unknown, not none. sbx warns once at setup.
  - `network.mode = "egress"` is refused, since its `connect()` decisions are made through the listener.
  - `seccomp.deny` may include `sendmsg`, which is reserved only to hand the listener over. `execve` stays reserved.
  - `sbx probe` runs the check "seccomp filter" instead of "seccomp user notification": in a forked child, the prelude and a one-rule filter (`getppid` → the policy's verdict), and the outcome must match the verdict.
- **Example:** `policy/gvisor.example.toml`: Landlock off, `notify = "off"`, `on_violation = "kill"`, cgroup off, network none, sampling off. The image ships and validates it.

## Design

- **Policy (`src/policy.rs`):**
  - `Notify { Listener, Off }`, the first field of `SeccompCfg`.
  - `validate_network` refuses egress with `Off`.
  - `validate_seccomp` asks `seccomp_layer::reserved(name, notify)` for the reason a syscall cannot be denied, and warns once for `Off`, with a text for each verdict.
- **Filter (`src/seccomp_layer.rs`):**
  - `OnMatch { Notify, Verdict(Violation) }`, mapped purely from the policy. `compile(table, on_match)` emits the marker rewritten into `USER_NOTIF`, `SeccompAction::Errno(EPERM)` or `SeccompAction::KillProcess`.
  - `Programs` carries `on_match`.
  - `install_without_listener` installs with flags 0.
  - `sendmsg` moves into the names `seccomp.deny` accepts.
- **Supervisor (`src/supervisor.rs`):**
  - The socketpair, the listener handover (`Stage::Listener`) and the notification thread exist only with `Notify`.
  - Without them, the close-on-exec pipe's EOF still means that `execve` succeeded.
  - `denials` is `Some` exactly when a dispatcher ran.
  - A program killed by SIGSYS under `Verdict(Kill)` gets a hint in its log line.
- **Probe (`src/capabilities.rs`):** the check is chosen by `notify`. The new one goes through the real `compile` path, with `RLIMIT_CORE` set to 0 in its child.
- **Report (`src/report.rs`):** `Ran.denials: Option<Vec<…>>`; a setup failure keeps `[]`. The report keeps its 12 keys.

## Tests

- **Property tests:**
  - for any policy (any `notify` and `on_violation`) and any syscall number and arguments, the compiled program returns the policy's match verdict exactly when `RuleTable::evaluate` matches, and `ALLOW` otherwise. The verdict comes from literals in the test, so the mapping is checked too.
  - the prelude's verdicts, for any number and architecture.
- **Unit tests:**
  - egress with `notify = "off"` is refused
  - `sendmsg` and `execve` in `seccomp.deny`
  - the upgrade hint and the warning
  - `denials: null` in the report
- **Smoke (`tests/smoke.py`, normal kernel):**
  - a section for `notify = "off"`: the probe, kill (159, `{"signaled": 31}`, in a child too), errno (`EPERM`), AF_UNIX, the two filters, egress refused, `sendmsg`, and the hint for a missing key
  - `tests/image-checks.sh`: the gVisor example's probe passes on runc.
- **gVisor:**
  - `tests/gvisor.py` runs as a Modal sandbox's own command. It is stdlib only.
  - `tests/modal_gvisor.py` is a uv script with modal pinned and a lock file. It checks the static amd64 binary, builds the sandbox image and streams the suite.
  - `make gvisor` builds the amd64 image, extracts sbx and runs the script.
