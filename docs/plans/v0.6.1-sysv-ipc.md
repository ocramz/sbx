# v0.6.1: SysV IPC and POSIX message queues in `seccomp.deny` (#20)

## Context

gVisor has SysV IPC but no `/proc/sysvipc`: the root `/proc` entries in gVisor's `pkg/sentry/fsimpl/proc/tasks.go` are `cmdline`, `cpuinfo`, `devices`, `filesystems`, `loadavg`, `sys`, `bus`, `fs`, `irq`, `meminfo`, `modules`, `mounts`, `net`, `sentry-meminfo`, `stat`, `sysrq-trigger`, `uptime` and `version`. A runtime that skips a listing that doesn't exist lets a segment carry data from one round to the next unseen. Walking the objects instead doesn't work there either: gVisor's `shmctl` takes `SHM_STAT` as `IPC_STAT`, by id rather than by index, and has no `SHM_STAT_ANY`; `msgctl`'s `MSG_STAT` does the same.

**User decision (2026-11-27):** deny `shmget`, `semget` and `msgget` under gVisor. A step that calls one is killed by SIGSYS (`notify = "off"`, `on_violation = "kill"`).

sbx v0.6 refuses those names: `seccomp.deny` takes only names `seccomp_layer::lookup` knows (`DEFAULT_DENY`, `DEFAULT_DENY_ARCH`, `EXTRA_NAMES`, `EXTRA_NAMES_ARCH`), and none of `shmget`, `semget`, `msgget` or `mq_open` is there, so validation fails with `seccomp.deny: unknown or unsupported syscall "shmget"`.

## User-visible behaviour

- `seccomp.deny` may name `shmget`, `semget`, `msgget` and `mq_open`. They are names a policy may deny, not defaults: no policy changes unless it names them, and every v0.6 policy still validates.
- A denial is like any other: with the listener it is logged and counted under the call's name; without it the kernel applies `on_violation`.
- Neither x86-64 nor aarch64 has the `ipc(2)` multiplexer that i386 routes SysV calls through, and the prelude kills a foreign architecture's calls and returns `ENOSYS` for x32. So these four are the only ways to create a SysV object or a POSIX queue.
- `mq_open`: POSIX queues live in the mqueue filesystem. A runtime that empties `/dev/mqueue` between steps covers them only where it is mounted; elsewhere `mq_open` can be denied by the same rule.
- Nothing else: no new key, no change to the filter's shape, the report, the probe or the defaults.

## Design

- `src/seccomp_layer.rs`: `SYS_shmget`, `SYS_semget`, `SYS_msgget` and `SYS_mq_open` join `EXTRA_NAMES`, the list for both architectures. libc 0.2.191's musl bindings have all four on both targets:

  | | x86-64 | aarch64 |
  |---|---|---|
  | `mq_open` | 240 | 180 |
  | `msgget` | 68 | 186 |
  | `semget` | 64 | 190 |
  | `shmget` | 29 | 194 |

  `lookup`, `syscall_name` and `build_table` already read `EXTRA_NAMES`.

## Tests

- **`names()`:** `lookup` gives each of the four its number, `is_default_denied` is false, and `syscall_name` names it.
- **Validation:** `deny = ["msgget", "mq_open", "semget", "shmget"]` validates with `notify = "listener"` (no warnings) and with `"off"` (only the notify-off warning).
- **Property test** over `run_bpf`: for any policy, adding the four to `seccomp.deny` makes each of their numbers, with any arguments, return the policy's match verdict, under either `notify` and `on_violation`, and leaves the verdict on every other syscall unchanged. The four also join `samples()`.
- **`tests/smoke.py`:** `shmget(IPC_PRIVATE, 4096, 0600)` through ctypes:
  - works under the base policy (the control);
  - with the four denied, `notify = "listener"`, `on_violation = "errno"`: fails with `EPERM`, counted in `denials` as `shmget`;
  - with the four denied, `"off"`, `"kill"`: SIGSYS (exit 159, `{"signaled": 31}`), `denials: null`.
- **`tests/gvisor.py`** (`make gvisor`): the same call works under the example policy and kills by SIGSYS with the four denied. The platform facts record whether `/proc/sysvipc` exists and whether `/dev/mqueue` is mounted.

## Docs and release

- **README:** the seccomp paragraph names the four among what `seccomp.deny` may add, for a sandbox where the runtime can't list or remove IPC objects; a bullet under "Without the listener"'s gVisor notes; the `make gvisor` paragraph.
- **`policy/gvisor.example.toml`:** a commented `deny = ["msgget", "semget", "shmget"]`, with the reason.
- **CHANGELOG:** v0.6.1, "Added: `seccomp.deny` may name `shmget`, `semget`, `msgget` and `mq_open`".
- **Version:** `Cargo.toml` 0.6.1. The tag is the user's to choose.
- **Costs:** no SysV IPC and no POSIX queues for a program under such a policy: it is killed, and a wrapper's step fails as a policy violation. POSIX shared memory in `/dev/shm` and file descriptors stay allowed (PyTorch's DataLoader, NCCL, Python's `multiprocessing`, glibc's POSIX semaphores). Without the listener, a forked child's denial shows only through its parent; what it would have made is never made.
- **Out of scope:** the wrapper's pin of the release digest and its `SBX_VERSION`.
