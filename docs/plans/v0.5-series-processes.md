# v0.5, part 2 of 3: per-process entries in the memory series

Follows [v0.5-series.md](v0.5-series.md). Next: [v0.5-series-compression.md](v0.5-series-compression.md).

## Context

Part 1's rows hold per-sample aggregates. To attribute memory to processes, each row also lists the largest processes of that sample.

**User decision:** rows stay exact. Each row lists at most `max_processes` processes, and an "others" remainder covers the rest, so the figures add up to the sample.

**Defaults chosen:**
- A process is (pid, start_ticks), with start_ticks from field 22 of `/proc/<pid>/stat`, so a recycled pid is a new process.
- Its name is the one from the latest sample that lists it (`exec` changes it). It is escaped like log lines (`log::untrusted_bytes`).
- Processes are ranked by RssAnon + RssFile + RssShmem, ties broken by (pid, start_ticks).

## User-visible behaviour

- **Policy:** `[measure.series] max_processes = 32` (0..=4096; 0 = none) is required with `mode = "on"`. The bound includes the entries and the process table.
- **File:**
  - **New `rows` columns:** `others_processes`, `others_anon_kib`, `others_file_kib`, `others_shmem_kib`.
  - **`processes`:** `{"pid": [], "start_ticks": [], "name": []}`.
  - **`process_rows`:** `{"row": [], "process": [], "anon_kib": [], "file_kib": [], "shmem_kib": []}`, ordered by row, then by rank. `process` indexes `processes` and `row` indexes `rows`.
  - **With `max_processes = 0`:** `processes`, `process_rows` and the `others_*` columns are `null`.
  - **The sums:** the listed entries plus `others` add up exactly to the sample's processes. For example, the anon entries plus `others_anon_kib` equal `tree_anon_kib`.
  - **The header** gains `max_processes`.

## Design

- **Process identity:**
  - `ProcStat` gains `StartTicks(u64)`. `ProcEntry` carries it, and `live_descendants` returns `BTreeMap<Pid, StartTicks>`.
  - **`ProcDir` (memory.rs, IO):**
    - opens `/proc/<pid>` as a directory fd and reads `stat` through it. A different start_ticks counts as gone.
    - reads `status` through `openat`, and the `fd` directory through `openat`, `fdopendir`, `readlinkat` and `fstatat`.
    - The figures and memfds then belong to that exact process, which closes the race between `proc_table` and the reads.
  - `Tracker` gets only verified pids in `measured`.
- **`Sample.procs`:**
  - becomes `Vec<ProcRead { key: ProcKey, name: Comm, mem: ProcMem }>`
  - `Comm` is a 16-byte array plus its length (the kernel's TASK_COMM_LEN)
- **`src/series.rs`:**
  - **`Row`** gains `top: Vec<(Slot, ProcMem)>`, at most `max_processes` entries, and `others: { count, anon, file, shmem }`.
  - **The process table** is `BTreeMap<ProcKey, Slot>` plus `Vec<(ProcKey, Comm)>`, with the name updated to the latest. Slots are dense because recording only stops and nothing is ever removed.
  - **`bound()`** = `max_samples × (row + max_processes × (entry + table entry))`.
- **`src/capabilities.rs`:** the functional `sandbox /proc access` check reads its child through `ProcDir`.

## Tests

- **Property tests:**
  - `listed_processes_are_the_largest_of_their_sample`, against brute force
  - `listed_and_others_add_up_to_the_sample`
  - `the_process_table_holds_exactly_the_listed_processes_with_their_latest_name`
  - `a_recycled_pid_is_a_new_process`
  - `process_rows_point_at_existing_rows_and_processes`
  - the part 1 properties again, with processes that come and go and pids that are reused
  - stat parsing extended to start_ticks
- **Smoke tests:**
  - children with distinct names and heap sizes appear, with their pids and names, and the largest is listed first
  - with `max_processes = 1`, the sums equal `tree_anon_kib` exactly
  - a fork loop that reuses pids stays within the bound
  - the probe still passes
