# Issue #10: record memory by kind — prepare v0.4

## Context

The report's only memory figure is `rusage.max_rss_kib` (`ru_maxrss`). As a measure of what a patch costs it is wrong in both directions:
- it counts the file pages of the binary and its libraries, which no patch controls (about 45% of servo's reading);
- it misses memory a patch does use but does not map: an unmapped memfd, a tmpfs or `/dev/shm` file, a detached SysV segment. A candidate could move a cache into one of them and read a lower RSS.

On Cloud Run there is no delegated cgroup, so the per-process `/proc` path must work on its own; with a delegated cgroup its `memory.stat` is read as well.

sbx samples the sandbox's memory by kind at an interval the policy sets and reports the peaks under a new `memory` key. This becomes v0.4.

**User decisions:**
- `unsampled_processes` counts the processes sbx reaped itself (the program and orphans reparented to sbx) that no sample saw. A process reaped by its own parent is not seen by sbx; the README says so.
- Sampling needs CAP_SYS_PTRACE: without it the sandbox's fd tables cannot be read, and the sandbox could hide them with `prctl(PR_SET_DUMPABLE, 0)`. sbx refuses to start without it (stage `capabilities`).

**Defaults chosen:**
- The shipped policies say `memory_sample_ms = 0` and `tmpfs = []` (v0.3's behaviour), as v0.3 shipped `[cgroup] mode = "off"`.
- Only the fields the report uses are read: VmRSS is the sum of the three Rss* fields, and `memory.stat`'s `file` and `file_mapped` are not reported.
- No new setup stage: the tmpfs baselines are read before fork, at stage `launch`.

## User-visible behaviour

**Policy:** a new required table.
```toml
[measure]
memory_sample_ms = 20      # 0 = off
tmpfs = ["/dev/shm"]       # tmpfs mounts whose use is measured; only with sampling on
```
- `memory_sample_ms` is 0 or at most 60000. `tmpfs` must be empty when it is 0.
- Each tmpfs path is absolute, canonical, listed once, a mount point, and a tmpfs (`statfs` magic); no two are the same filesystem.
- A missing table is an error with the hint "[measure] is new in sbx v0.4; add it with memory_sample_ms = 0 and tmpfs = [] to keep v0.3's behaviour". Breaking change; CHANGELOG has the snippet.

**Report:** a 12th key, `memory`, null when sampling is off or the program never started:
```json
"memory": {"interval_ms": 20, "samples": 153,
           "max_anon_kib": 1, "max_file_kib": 1, "max_shmem_kib": 1, "tree_peak_anon_kib": 1,
           "memfd_peak_kib": 1, "sysv_shm_peak_kib": 1, "tmpfs_peak_kib": {"/dev/shm": 1},
           "cgroup": {"peak_anon_kib": 1, "peak_shmem_kib": 1} | null,
           "unsampled_processes": 0}
```
- `max_*_kib`: the largest single process, per kind, over all samples (as `max_rss_kib` is).
- `tree_peak_anon_kib`: the largest sum of `RssAnon` over the sandbox's processes in one sample; copy-on-write pages shared after fork count once per process.
- `memfd_peak_kib`: memfds open in any sandbox process, each counted once (by device and inode), by allocated blocks.
- `sysv_shm_peak_kib`: resident SysV segments of the sandbox uid (owner or creator) or created by a sandbox process.
- `tmpfs_peak_kib`: per listed mount, the use above its level when sbx started.
- `cgroup`: with a delegated cgroup, the sandbox cgroup's `memory.stat` `anon` and `shmem` (which counts memfd, tmpfs and SysV pages by itself).
- Sampled peaks are lower bounds: whatever rises and falls between two samples is missed. `rusage.max_rss_kib` stays the exact single-process total.

## Design by component

**`src/policy.rs`**
- `RawMeasure { memory_sample_ms: u64, tmpfs: Vec<PathBuf> }` (`deny_unknown_fields`) ↔ `enum MeasureCfg { Off, Sampled { interval_ms: NonZeroU64, tmpfs: Vec<PathBuf> } }` via `try_from`/`into`, like `CgroupCfg`. `Off` with a non-empty `tmpfs` is a parse error.
- `Policy.measure` after `cgroup`; `validate_measure` for the bound and the tmpfs paths.

**`src/memory.rs` (new), pure part**
- Parsers, each with a test-only renderer: `ProcMem::parse_status` (`RssAnon`, `RssFile`, `RssShmem`, kB; None for zombies and kernel threads), `CgroupMem::parse` (`memory.stat` through `cgroup::keyed`), `parse_sysvipc_shm` (columns by header name).
- `sysv_bytes(segments, uid, pids)` and `memfd_bytes(entries)` (deduplicated by device and inode).
- `Sample` and `Peaks::fold(self, &Sample) -> Peaks`: pointwise maxima.
- `Tracker`, the state machine behind `unsampled_processes`: after each sample `sampled = (sampled ∩ present) ∪ measured` (`present` includes zombies, so a recycled pid starts afresh); when sbx reaps a pid, it counts as unsampled unless it was in `sampled`.

**`src/memory.rs`, IO part: `Sampler`**
- `Sampler::new(&MeasureCfg, uid)` reads each tmpfs baseline (`statfs`: `(f_blocks - f_bfree) * f_bsize`), before fork.
- `sample(live, present, cgroup)`: for each live sandbox pid, `/proc/<pid>/status` and the `/memfd:` links in `/proc/<pid>/fd` (`stat` through the link for device, inode and blocks); then `/proc/sysvipc/shm`, the tmpfs mounts, and `memory.stat` when delegated. A process that exited meanwhile (ENOENT, ESRCH) is skipped; any other error is logged once per kind and sampling goes on.
- `finish()` gives the report's `memory`.

**`src/supervisor.rs`**
- `live_descendants` returns the set of pids; `leftovers` counts it.
- `supervise` wakes for the next sample as it does for the deadline and the grace period, samples, and samples once more right after the program's process is reaped, before the tree is killed (leftovers, tmpfs files and segments still there).
- Every reaped pid also goes to the sampler's tracker.

**`src/cgroup.rs`:** `Delegation::memory_stat()`; `memory.stat` joins the files the sandbox cgroup must have.

**`src/capabilities.rs`:** with sampling on, the `CAP_SYS_PTRACE` check (its message names the reason) and a functional check: a child running as the sandbox uid makes itself non-dumpable, and sbx must read its `/proc/<pid>/status` and `/proc/<pid>/fd`, and `/proc/sysvipc/shm`.

## Tests

**Property tests (pure logic):** parse ∘ render = id for the three parsers; `Peaks::fold` is monotone, idempotent and independent of sample order; `memfd_bytes` ignores duplicates and order; `sysv_bytes` keeps exactly the matching segments; `Tracker` against a brute-force model; `MeasureCfg` through `sbx policy` and its errors; `live_descendants` as a set.

**`tests/smoke.py`:** `policy(measure=...)`; the 12-key report; a new section "memory by kind":
- a Python program that touches a 64 MiB heap, maps a 16 MiB memfd, writes a 32 MiB memfd it never maps, an 8 MiB `/dev/shm` file and a 4 MiB detached SysV segment, holds them, then cleans up: each figure is reported within one sample's slack, with sampling on; with it off `memory` is null;
- `unsampled_processes` for a program that exits before the first sample;
- refusals: a path that is not a tmpfs mount, `tmpfs` with sampling off, no CAP_SYS_PTRACE;
- the overhead: wall time of a CPU-bound program with sampling off and at 10, 20 and 50 ms (printed, with a loose bound);
- under `TEST_REQUIRE_CGROUP`: `memory.cgroup` from the delegated cgroup.

**`tests/live.py`:** the memory program on Cloud Run, where only the `/proc` path exists.
